## The problem

Ship recycling has to satisfy multiple regulatory frameworks (Hong Kong Convention, Basel Convention, EU SRR, ILO Guidelines) at the same time, sequence safe cutting operations across hundreds of components, track hazardous materials inventory across the whole vessel, and produce an economically viable plan. In practice that work is split across separate experts and separate spreadsheets, with the cross-checks done by hand. The brief was a single expert system that turns ship intake data into compliant, safe, economically viable recycling plans, with all four regulatory frameworks evaluated in parallel.

## Constraints

- **Multi-framework compliance**: HKC, Basel, EU SRR, and ILO Guidelines evaluated simultaneously. No assumption that one preempts another.
- **Critical-path-aware sequencing**: workflow order matters because of safety dependencies (you cannot cut into a tank that has not been gas-freed).
- **Combine declared and inferred hazards**: declared IHM is the ground truth where it exists; for everything else, hazards are inferred from age, type, and equipment.
- **Audience-specific reports**: the regulator, the recycling yard, the insurer, and the owner all want different cuts of the same plan.

## Approach

**Intake to ship profile.** A wizard captures 40+ parameters (vessel type, age, tonnage, equipment manifest, declared IHM, last drydock, propulsion, paint history). The output is a structured ship profile that every downstream module reads from.

**Hazmat identification.** 15 hazardous-material categories (asbestos, PCBs, ODS, anti-fouling biocides, heavy metals, etc.). Where the ship has a declared Inventory of Hazardous Materials, that is treated as primary truth. Where it does not, hazards are inferred from age, type, and equipment using a deterministic rule set. Both paths produce the same structured hazard record.

**Structural decomposition.** Four-tier component hierarchy: primary (hull, decks), secondary (bulkheads, frames), tertiary (stiffeners, brackets), non-structural (fittings, machinery foundations). The cutting sequence ordering depends on which tier a component sits in, so this hierarchy underpins everything safety-related.

**Workflow DAG and critical path.** A catalog of 204 standardised activities. Each activity has prerequisites (which produce a directed acyclic graph), durations, required certifications, and produced waste streams. Kahn's algorithm topologically sorts the DAG; the critical path is identified using duration-weighted longest-path. The output is a sequenced workflow with clear bottlenecks.

**Multi-framework compliance.** Each of HKC, Basel, EU SRR, and ILO Guidelines is implemented as an independent rule engine that consumes the ship profile + hazard record + workflow plan and emits structured compliance findings. All four run in parallel; nothing assumes one preempts another. A single non-compliance finding under any framework surfaces in the consolidated report with the specific clause violated.

**Risk matrix.** A standard 5×5 severity-by-probability grid maps to four risk classifications (Critical, High, Medium, Low). Each identified hazard gets placed in the grid based on the ship profile and the planned mitigations. The output drives where additional controls are required.

**Economic analysis.** Material recovery revenue (steel, copper, aluminium by weight, with regional pricing assumptions), labour and equipment cost breakdown, and a sensitivity sweep at ±30% on the dominant uncertainties. Reported alongside compliance and risk so the trade-offs are visible.

**Seven report types.** SRP (Ship Recycling Plan), Compliance, Hazmat, Safety, Environmental, Economic, Workflow. Each report serves a different audience and is generated to PDF via WeasyPrint with consistent branding.

## What broke

The first version of the critical-path output sorted the DAG topologically but did not weight by duration. Optimisers latched onto the first valid sequence regardless of how long it actually took, which produced plans that were technically dependency-correct and operationally absurd. Adding duration-weighted longest-path computation on top of Kahn's sort fixed it. The lesson: a topological sort is not a critical path, and downstream code will assume it is unless you make the distinction explicit.

## What I would do differently

Ship the framework comparison view (HKC vs Basel vs EU SRR vs ILO side by side) earlier. Stakeholders kept asking "what changes if we drop framework X" comparisons that the original UI did not surface. The compliance engine could already answer those queries; the UI just had not exposed them.
