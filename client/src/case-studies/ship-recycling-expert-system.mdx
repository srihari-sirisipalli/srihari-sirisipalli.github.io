## The problem

Ship recycling has to satisfy multiple regulatory frameworks (Hong Kong Convention, Basel Convention, EU SRR, ILO Guidelines) at the same time, sequence safe cutting operations across hundreds of components, track hazardous materials inventory across the whole vessel, and produce an economically viable plan. In practice that work is split across separate experts and separate spreadsheets, with the cross-checks done by hand.

This system turns ship intake data into compliant, safe, economically viable recycling plans, with all four regulatory frameworks evaluated in parallel.

## Intake to ship profile

A wizard captures 40+ parameters (vessel type, age, tonnage, equipment manifest, declared IHM, last drydock, propulsion, paint history). The output is a structured ship profile that every downstream module reads from.

## Hazmat identification

15 hazardous-material categories (asbestos, PCBs, ODS, anti-fouling biocides, heavy metals, and others). Where the ship has a declared Inventory of Hazardous Materials, that is treated as primary truth. Where it does not, hazards are inferred from age, type, and equipment using a deterministic rule set. Both paths produce the same structured hazard record.

## Structural decomposition and cutting sequence

Four-tier component hierarchy (primary, secondary, tertiary, non-structural) drives a five-phase safe cutting sequence. You cannot cut into a tank that has not been gas-freed, so hierarchy is a safety property, not a taxonomy.

## Workflow DAG and critical path

A catalog of 204 standardised activities, each with prerequisites, durations, required certifications, and produced waste streams. Kahn's algorithm topologically sorts the DAG; duration-weighted longest-path identifies the critical path. The output is a sequenced workflow with clear bottlenecks.

## Multi-framework compliance

HKC, Basel, EU SRR, and ILO Guidelines each run as an independent rule engine that consumes the ship profile, hazard record, and workflow plan, and emits structured compliance findings. All four run in parallel; nothing assumes one preempts another. A single non-compliance finding under any framework surfaces in the consolidated report with the specific clause violated.

## Seven audience-specific reports

SRP (Ship Recycling Plan), Compliance, Hazmat, Safety, Environmental, Economic, Workflow. The regulator, the yard, the insurer, and the owner each want a different cut of the same plan. Each report renders to PDF via WeasyPrint with consistent branding.

## What broke

The first version of the critical-path output sorted the DAG topologically but did not weight by duration. Optimisers latched onto the first valid sequence regardless of how long it actually took, which produced plans that were technically dependency-correct and operationally absurd. Adding duration-weighted longest-path fixed it. Lesson: a topological sort is not a critical path, and downstream code will assume it is unless you make the distinction explicit.
