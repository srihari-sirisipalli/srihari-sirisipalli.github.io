## What it is

Pangeon is a startup studio. Intellipat is one of its portfolio startups — an LLM-powered patent product. It finds prior art for a query patent using embedding retrieval to narrow the field, then an LLM to score each candidate on how close it really is.

## What I did

The stack ran on always-on EC2 instances. Prior-art search is bursty by nature, so most of the time the boxes sat idle and the bill did not.

I reshaped the compute as a coordinator Lambda that fans out to a pool of scoring Lambdas. Cold starts on the embedding container were the obvious risk, so the coordinator path has pre-warmed concurrency. That kept perceived latency low without paying for permanent capacity on the scoring side.

Retrieval is FAISS over patent abstract embeddings, sharded by classification block. The coordinator narrows the candidate set before the expensive LLM scoring runs. The LLM drives the unit cost, so any hit to its call count compounds everywhere else.

Two levels of parallelism worth naming. Per request, the scoring fan-out is async to AWS. Inside each Lambda, the batch scoring loop is multiprocessed. Both bounded by configuration, both visible in CloudWatch.

Every client account gets the same stack via Terraform: Amplify front, Lambda compute, IAM, monitoring, security baseline. New environments are a `terraform apply`, not a runbook.

## What broke

The initial Lambda concurrency limit clipped the fan-out under burst. The queue grew faster than the function scaled. A CloudWatch dashboard tracking invocations against the concurrency cap made it obvious. Raise the cap, add a fall-through to async invocation, and peak-day throughput stopped degrading.

The vector store also needed re-sharding twice as the corpus grew. Worth doing earlier next time.
