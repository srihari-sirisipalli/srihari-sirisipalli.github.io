## The problem

Patent prior-art search at scale is two coupled problems: (1) you need semantically meaningful similarity between long, jargon-heavy documents, and (2) you need to evaluate thousands of pairs per day without paying enterprise-grade infrastructure rates. The original system at Pangeon ran the embedding + scoring stack on always-on EC2 instances. Throughput was bounded by node count, costs were bounded by node uptime, and both were higher than they should have been for a workload that's bursty by nature.

## Constraints

- **Throughput floor**: 1,000+ similarity evaluations per day, with day-of bursts well above that.
- **Latency ceiling**: humans wait on this. First results must surface in seconds, not minutes.
- **Cost ceiling**: trim infra spend without making the system fragile under burst.
- **Reproducibility**: cross-account deploys for client environments. IaC must be the source of truth.

## Approach

**Re-architecting onto Lambda.** The dominant cost on EC2 was idle capacity. Instances sized for peak burst sat near-empty 80%+ of the time. Re-shaping the workload as a coordinator Lambda + a fan-out of scoring Lambdas matched the bursty traffic pattern directly. Cold starts for the embedding container were the obvious risk; pre-warmed concurrency on the coordinator path solved the user-perceived latency without paying for permanent capacity on the scoring path.

**Vector retrieval.** FAISS index built over patent abstract embeddings, sharded by classification block. Top-k retrieval on the coordinator side narrows the candidate set before LLM scoring is paid for. The LLM is the unit-cost driver, so anything that reduces its call count compounds.

**Async + multiprocessing.** Per-request, the scoring fan-out is async to AWS; per-Lambda, the inner loop uses multiprocessing for batch scoring of the candidate window. Two independent levels of parallelism, both bounded by configuration, both visible in CloudWatch.

**Terraform IaC.** Every account gets the same stack via Terraform: Amplify front, Lambda compute, IAM, monitoring, security baseline. New client environments are a `terraform apply` away, not a runbook.

## What broke

Initial Lambda concurrency limits clipped the scoring fan-out under burst. The queue grew faster than the function scaled. Catching it required a CloudWatch dashboard that explicitly tracked invocations vs concurrency cap rather than just function errors. Once the cap was raised and a fall-through to async invocation was added, peak-day throughput stopped degrading.

The vector store also needed re-sharding twice as the corpus grew. The first split was by classification chunk and got hot for a couple of common classes; the second pass added a secondary hash dimension. Worth doing earlier next time.

## What I'd do differently

Bake batch-mode evaluation into the API from day one. The system was built for interactive scoring and grew batch endpoints later, which would have been simpler if planned alongside the original design.
