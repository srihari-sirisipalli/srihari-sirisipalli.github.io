## What it is

An offline PDF organiser. You drop a folder of messy PDFs, DocForge reads each one with a local vision-language model and produces clean descriptive filenames and a real folder structure. Everything runs on the machine. Nothing leaves.

Open source on GitHub. Cross-platform (Windows, macOS, Linux). Ships as a Python package and a CLI.

## The five-stage pipeline

Each PDF flows through the same pipeline. Stages are independent, resumable, and swappable.

1. **Metadata extraction.** PDF info dictionary, page count, file hash. Cheap, deterministic, always runs first.
2. **Text probe.** Extract embedded text and score its quality. If a PDF is a real text PDF, later stages can skip the vision pass.
3. **Content extraction.** Either a VLM vision pass (default, when Ollama is available) or a heuristic fallback (regex, font-size title detection, keyword classification). No GPU, no problem.
4. **Field merging.** Combine what the VLM saw with what the heuristics and metadata gave you. Resolve conflicts with rules, not with a black box.
5. **Filename generation.** VLM-suggested name, or a template built from the merged fields.

## VLM naming

When Ollama is installed, DocForge renders each PDF page as an image and asks a local vision-language model to name it. The model sees titles, logos, dates, stamps, and layout the way a human would. Three supported models today: `minicpm-v` (best), `llava` (good), `moondream` (lightweight, runs on 4 GB RAM).

Model comparison, install, and pull are all first-class CLI commands (`docforge model list`, `docforge model pull`).

## Heuristic fallback

No Ollama, no GPU, no problem. The heuristic path uses largest-font-in-page detection for titles, regex for dates and IDs, keyword scoring for document type, and template assembly for the final name. Fast enough to process a hundred PDFs in seconds.

## OCR for scans

Tesseract integration for image-only PDFs. Detected automatically when the text probe comes back empty.

## Safety and reversibility

- **Dry-run by default.** `docforge process ~/pdfs` shows what would change. Nothing is renamed until `--execute`.
- **Full rollback.** Every rename and move is tracked with a job ID. `docforge rollback <job-id>` puts things back.
- **Local SQLite state.** Everything is in `~/.docforge/state.db`. Auditable, portable, deletable.

## Organisation strategies

Sorts files by type, year, domain, or nested combinations. The `domain_type` strategy produces trees like:

```
organized/
├── academic/       (certificate, project_report)
├── employment/     (offer_letter, contract)
├── financial/      (invoice)
├── identity/       (id_card, license)
└── general/        (other)
```

## Multi-format export

Export the full processing result to Excel, JSON, CSV, or Markdown. One command: `docforge export -f excel`.

## Requirements

- Python 3.10+
- Ollama (optional, for VLM)
- Tesseract (optional, for OCR)
- Runs on 4 GB RAM in heuristic-only mode, 8+ GB with `minicpm-v`

## Why it exists

Every professional accumulates a folder full of scanned PDFs with names like `IMG_3847.pdf` and `Copy of Final_v2_FINAL.pdf`. Cloud OCR services want your documents on their servers. DocForge is the version of that tool that never asks.
