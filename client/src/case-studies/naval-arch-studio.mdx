## The problem

Naval-architecture computation at the early-stage hull-design level is dominated by expensive commercial software (Maxsurf-class). For independent analysts, small yards, and academic groups, that pricing locks the discipline behind a paywall. The brief was to build an open-source Python-first naval-architecture suite that covers the full pipeline an analyst actually uses (hydrostatics, stability, seakeeping, damage, structural strength, classification compliance), validates against the commercial reference, and produces branded reports clients accept.

## Constraints

- **Validate against the industry standard**: parity with Maxsurf at typical loading conditions has to be tight enough to be defensible.
- **Cover the full design pipeline**: hydrostatics through damage stability through classification rules. Each gap is a reason to fall back to commercial.
- **Branded multi-page PDF reports**: deliverables need to look like deliverables.
- **Laptop-runnable**: no cloud, no cluster. The hardware budget assumption is one well-specced laptop.

## Approach

**Hydrostatics with selectable integration.** Nine integration methods to choose from (Simpson, Gauss, trapezoidal variants, etc.) so the analyst can match the convention of whatever validation reference is in play. Bonjean curves drop out of the same evaluator. Validated against Maxsurf at a 4,759 t displacement match before the rest of the suite was layered on top.

**Stability code coverage.** GZ curves, IMO IS Code 2008 intact criteria, and the weather criterion live in the intact-stability module. SOLAS probabilistic damage with an attained subdivision index calculation lives in the damage module. Both share the same heeling-equilibrium solver so a result in one is consistent with a result in the other.

**Classification rules as code.** IACS rule loads, hull-girder compliance, plate buckling, IRS Sec. 15.4–15.5 design motions, and DNV-GL fatigue (Palmgren-Miner damage accumulation with S-N curves) are codified as rule modules. Each module emits a structured pass/fail with the governing equation surfaced in the output, so a class society reviewer can trace the calculation back to the rule clause.

**13 GUI workspaces with side-by-side comparison.** Each domain module gets its own workspace. The cross-cutting feature most analysts ask for first is loading-condition comparison: pick two or three cases and have GZ curves, motions, and bending moments plotted side by side. ReportLab assembles the branded multi-page PDF when the analyst is ready to deliver.

**Tests as the validation contract.** ~450 tests across the 13 modules, with the Maxsurf parity case treated as a first-class regression. New module work that breaks the parity test does not merge.

## What broke

The first seakeeping module produced plausible-looking but wrong RAOs because the wave-spectrum integration sampled too coarsely at low frequencies. JONSWAP results from a published reference paper failed the parity check. Re-sampling with a denser low-frequency mesh and switching to a quadrature better suited to the spectral shape brought the RAOs into agreement.

## What I would do differently

Adopt a single canonical units library across the suite from day one, rather than normalising units at module boundaries. A handful of subtle bugs traced back to mixed units (m/s vs knots, kN vs kgf) sneaking through legacy code paths. A library-level convention removes the whole class.
