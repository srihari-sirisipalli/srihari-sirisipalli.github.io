## The problem

Off-the-shelf FEA packages for offshore structures are expensive, closed-source, and slow to iterate against. If you want to script a new analysis driver, embed FEA inside another tool, or check what a commercial solver actually computed, you cannot.

PyNAOS is a self-contained Python FEA engine that covers the analysis types offshore work actually needs (linear and non-linear static, eigenvalue, linear and non-linear dynamic, buckling), pairs them with offshore-specific physics, and ships with a desktop workstation that an analyst can drive without writing Python.

## Skyline storage and LDLT

Offshore-structure connectivity is sparse but banded (jacket members tie back to a small number of nodes). Skyline storage matches that pattern: only the active band per column is stored, factorisation works in place, and triangular solves are just descents through the band. For 3D Timoshenko beam meshes it beats dense storage by an order of magnitude on memory.

## Lanczos for eigenvalues

First-n modes are what offshore work actually needs (modal analysis for fatigue spectra, mass participation, buckling factors). Full factorisation is wasted work. Lanczos converges to the lowest-magnitude eigenvalues quickly, with re-orthogonalisation to keep numerical drift from contaminating the basis.

## Offshore physics

**Hydrodynamics.** Airy for linear shallow-water cases, Stokes 5th order for steeper non-linear waves, Chakrabarti for current-coupled regimes. Morison gives the force on slender members from the wave kinematics. The same output drives both static-equivalent and time-domain dynamic loading paths.

**Geotechnical foundations.** API RP 2A p-y and t-z curves wrap the soil-pile interaction. Depth-of-fixity gets computed from the p-y curve so the bottom of the structural model can be a clean fixed boundary at a realistic depth instead of dragging soil non-linearity through the whole solve.

## Desktop workstation

PyQt5 and OpenGL viewer over the Python core. Seven analysis workspaces (one per driver, plus model setup), validation and readiness checks before a run, command palette for power users, auto-save so an analyst never loses a half-set-up case.

## Tests as the contract

Around 600 tests at high coverage, with ten reference scenarios committed alongside expected outputs. New solver work that shifts a reference result at the fourth decimal place fails CI. Reference cases with expected outputs, committed to git, are the cheapest insurance you can buy on a numerics codebase.

## What broke

An early non-linear dynamic release silently used the small-strain assumption inside the P-Delta branch, which gave plausible-looking but slightly under-conservative top-of-jacket displacements. Caught it because a reference scenario flagged a regression at the fourth decimal place between releases. Inputs alone would not have caught it.
