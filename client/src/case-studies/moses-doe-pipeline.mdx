## The problem

Bentley MOSES is the offshore-engineering standard for sea-transport hydrodynamics, but it is a single-case GUI tool. To explore design space at any meaningful resolution you need to drive it programmatically across thousands of parameter combinations, parse its multi-format outputs, and feed the results into something that lets you ask new questions without re-running the simulator. None of that is built in.

The brief: characterise stability and motions for a large barge across a wide ballast envelope, then train surrogate models so engineers can iterate at design time instead of waiting for the next simulation queue.

## Stratified sampling

Uniform Latin Hypercube over 80 inputs leaves the operational corners under-sampled because MOSES outcomes are non-linear in ballast distribution. The fix was four-zone stratification (Light, Medium, Heavy, Mixed) with per-zone LHS, then concatenation and shuffling. The same code path generates train and test splits at sample time so downstream surrogate training is leakage-controlled.

## Resumable orchestration

Each case writes a marker file when it finishes parsing. Restarting the orchestrator skips any case whose marker exists. That single primitive cost an afternoon to implement and saved every subsequent re-run. Licensed software makes resumability a hard requirement, not a nice-to-have.

## Defensive parsing

Per-case output landed as one 12-sheet Excel workbook covering 6-DOF motions and accelerations at flotation and motion points, longitudinal bending moment and shear force, intact and damage stability across compartments, and weight distribution. The parser is paranoid by design: bad cases are quarantined, never silently dropped.

## Surrogates

Two heads: a stability classifier (passes IMO criteria yes or no) and a motion regressor (peak-period responses). XGBoost and LightGBM as the workhorses. A small PyTorch MLP for the motion targets where smoothness mattered. SHAP for feature attribution.

## Optimisation on top of the surrogate

Optuna for single-objective ballast tuning. PyMoo NSGA-II for the multi-objective stability-vs-motion frontier. Both run on top of the surrogate, not the simulator, so design iterations cost milliseconds instead of minutes.

## What broke

The first parser was naive about MOSES warning lines. Three of them shifted column offsets in a way that silently produced offset bending-moment values for a batch of cases. Caught it during sensitivity analysis when SHAP flagged a feature whose physical relationship made no sense. Lesson: parser tests using known-good reference cases should run before a long DOE batch, not after. The parser now re-validates against six reference checksums on every cold start.
