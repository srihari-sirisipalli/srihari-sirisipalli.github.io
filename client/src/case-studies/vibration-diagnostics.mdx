## The problem

Rotating machinery (motors, pumps, turbines, gearboxes) fails in a small number of characteristic ways: unbalance, misalignment, looseness, bearing defects, rotor bar issues, stator eccentricity. Each fault leaves a fingerprint in the vibration spectrum. Practitioners know these fingerprints well. What they need is a diagnostic tool that surfaces the right diagnosis with the right evidence, not a black-box classifier that just returns a label.

This rule engine ranks probable faults for a measurement with a traceable for-and-against evidence chain, so a maintenance engineer can read the reasoning, not just the verdict.

## Thirteen diagnostic rules

Unbalance, misalignment (angular and parallel), mechanical looseness, bearing defects (BPFO, BPFI, BSF, FTF), rotor bar defects, stator eccentricity, cavitation, and spectrogram-based transient fault detection. Each rule captures a specific fingerprint pattern in the frequency and time domains.

## Feature extraction

Thirty-plus features per measurement: FFT bands, Hilbert envelope, crest factor, kurtosis, harmonic and sideband detection, STFT transients. Every feature is physically motivated. The features feed the rules; the rules produce ranked hypotheses; the ranked hypotheses come with the specific evidence that supported them.

## Bearing math

Bearing defect frequencies (BPFO, BPFI, BSF, FTF) are computed from bearing geometry. Twelve pre-loaded SKF bearing profiles ship with the tool so common bearings can be diagnosed from a part number alone. Custom bearings just need the ball count, pitch diameter, ball diameter, and contact angle.

## ISO 10816 severity mapping

Overall vibration velocity gets mapped to ISO 10816 severity zones (A/B/C/D). Each diagnosis carries a confidence score and a severity score. Together they answer both "what is going on" and "how urgent is it."

## Six-tab PyQt5 workflow

Load a signal, extract features, run the rule engine, inspect evidence, review the ranked hypothesis list, export a report. A headless Python API mirrors the same workflow for teams that want to embed the diagnostics inside a larger CMMS or fleet-monitoring system.

## Why rules, not ML

An unsupervised ML detector is good at flagging that something is different from baseline. A rule engine is good at saying what the difference means. For fault diagnosis in rotating machinery, where practitioners already know the fingerprints, transparency is more valuable than adaptivity. The ML counterpart to this tool is a separate project ([MFDMS](/work/machine-fault-detection-ml)) that handles the "different from baseline" half.

## What broke

The first BPFO detection worked well on textbook cases and missed real bearings whose defect frequency landed inside a strong harmonic sideband. Adding narrow-band envelope demodulation ahead of the FFT gave the right signal the room it needed to show up. Lesson: the textbook signal processing pipeline sometimes has to be inverted for the real signal.
